What is this all about?

The Sierpinski triangle is a fractal shape, typically created by recursively subdividing an equilateral triangle into smaller triangles.

Another way to generate the Sierpinski triangle pattern is to use a random process, starting at a randomly selected corner, and repeatedly moving halfway between the current point and a randomly selected corner. This method is known as the "Chaos Game". After each move, the current point is marked black, and over time, the image of the Sierpinski triangle emerges.

Calculating the pattern

Due to the random nature of this process, the resulting pattern is a kind of 'probabilistic' estimation of the triangle. Over time,the pattern converges to the Sierpinski triangle, but at any given point in time, it may not be a perfect representation.

It's also somewhat computationally intensive. To cover a statistically significant portion of the triangle, a large number of iterations are required and, back in 2010 when this toy was created, browser javascript engines were not really able to run the process at a reasonable speed.

Instead, this method keeps the 'random walk' concept, but by understanding that the 'pick a random corner' is really just 'sample one of the possible paths', we can instead follow all possible paths at each turn (i.e. from each current position, create N new points each of which is halfway between the current point and one of the N shape corners), generating a uniform coverage of the sampled space much more quickly. Rather than track each current position in an array/list and iterate over it, we can instead use a single bitmap to represent all of the current positions, and update it in-place at each step, which is much more efficient.

Generalizing beyond a triangle

Now we have a method that is fast, and just interpolates between 'corners', the question becomes, does this pattern only appear for triangles? Why are triangles special? It's easy to try, and the result looks quite ugly, even if there are patterns to be seen:

The issue is that all of the corners are treading on each other's paths, so you can see structure, but everything is too harsh/contrasty. The obvious fix is to make each step have less impact. Rather than flip a 0 (white) to a 1 (black), we just make the value a little bit darker.

This means the visualization changes from 'did we visit this point?' to 'how frequently was this point visited?' and the result shows much more interesting structure:
